## Overview

This example demonstrates a custom **10 MHz Dual-SPI (DSPI)** implementation on the Shrike platform. By utilizing 2 data lines simultaneously, it doubles the throughput of standard SPI. 

The project uses the RP2040's Programmable I/O (PIO) to act as the DSPI master, generating the clock and bit-banging the dual data lines. On the FPGA side, it implements an oversampled target (slave) state machine that uses the ForgeFPGA's internal 50 MHz clock to detect SPI clock edges. It includes a loopback mechanism where data typed into the MCU serial console is transmitted via DSPI, captured by the FPGA, and echoed back, alongside periodic asynchronous heartbeat alerts generated by the FPGA.

You will learn how to bypass standard SPI limitations using PIO, handle bidirectional data lines (inouts), and implement clock-domain edge detection on the ForgeFPGA.

## Quick Start (Pre-Built Bitstream)

1. Connect the Shrike board via USB.
2. Upload `bitstream/dspi_10mhz_loopback.bin` using ShrikeFlash.
3. Run `dspi.py` on the RP2040 using Thonny or mpremote.
4. Open the serial monitor and type characters.
5. **Expected result:** The MCU will transmit the characters, and the terminal will print the echoed ASCII hex values returned by the FPGA. You will also see asynchronous heartbeat alerts when the FPGA initiates communication.

## Build From Source

### FPGA (Verilog)
1. Open the project in the Go Configure Software Hub.
2. Paste the Verilog for the `top` and `dual_spi_target` modules.
3. Configure I/O mapping in the Pin Constraints, ensuring `dual_rx`, `dual_tx`, and `dual_oe` map to pins 17 and 18 with output enable logic.
4. Generate the bitstream.

### Firmware (MicroPython)
1. Open `dspi.py` in Thonny.
2. Ensure the PIO state machine frequency is configured to `10_000_000` (10 MHz).
3. Run the script.

## How It Works

The design consists of three main components:

### 1. MicroPython PIO Master (`dspi.py`)
Uses the `@rp2.asm_pio` decorator to create a custom 2-wire SPI protocol at 10 MHz. The PIO state machine utilizes `out(pins, 2)` and `in_(pins, 2)` instructions to process two bits per clock cycle, effectively cutting the transmission time for a standard 8-byte payload in half.

### 2. `top` Module (FPGA)
Handles the 50 MHz internal clock domain for the status LED and the 100M-cycle heartbeat timer. It contains the logic to switch between sending the standard echo data and transmitting the `0xFF` alert code when the heartbeat timer triggers.

### 3. `dual_spi_target` Module (FPGA)
Implements an **oversampled** SPI slave. 
* Uses a 3-stage synchronizer (`sck_sync`, `cs_sync`) driven by the ForgeFPGA's internal 50 MHz system clock.
* Detects the rising edges of the 10 MHz SPI clock to safely shift data in and out.
* Manages the bus turnaround phase, using `o_dual_oe` to toggle the bidirectional pins from input (listening to MCU) to output (driving echo back to MCU) at the precise correct clock cycle.

## Top Module Interface

| Signal | Direction | Description |

Notes
Contiguous Pins: RP2040 PIO instructions like out(pins, 2) require the target GPIOs to be numerically sequential in the silicon. The Shrike's fixed SPI pins (SCK on GPIO 2, CS on GPIO 1) force the DSPI data lines to be mapped to the contiguous GPIO 14 and 15 interconnect block.

Turnaround Phase: Because DSPI uses the same 2 wires for transmitting and receiving, the PIO state machine and the FPGA FSM include specific delay logic (Turnaround Phase) to relinquish bus control and switch line directions without causing a hardware short circuit.
